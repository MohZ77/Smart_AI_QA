# 合同/条款文件审查

## 1. 能力

用户可以上传一份保险条款、合同或产品说明书，系统会：

1. 解析 PDF、DOCX、Markdown、TXT 或 HTML；
2. 按章节/条款分块；
3. 用 BM25 检索免责、等待期、理赔、退保、续保、费率、告知、争议解决等条款；
4. 生成初步风险审查报告，列出潜在风险、缺失条款和签约前核对项；
5. 返回可追溯的条款引用。

这不是正式法律意见，也不能替代律师或持牌顾问对合同效力、承保条件和理赔结果的审核。

## 2. 使用方式

工作台底部点击「文」上传文件，也可以直接调用：

```bash
curl -X POST http://localhost:8000/v1/chat/file \
  -F "file=@insurance-policy.pdf" \
  -F "question=请检查免责、等待期、理赔和退保条款，并说明合同是否具备进一步审阅的条件" \
  -F 'profile_json={"user_id":"u1","risk_level":"C3"}'
```

支持文件：`.pdf`、`.docx`、`.md`、`.markdown`、`.txt`、`.html`、`.htm`。

## 3. 审查维度

- 保险责任与保障范围
- 责任免除/免责
- 等待期/观察期
- 犹豫期
- 理赔条件、材料和时限
- 现金价值与退保损失
- 续保/保证续保
- 保费与费率调整
- 如实告知与核保
- 争议解决/管辖
- 特别约定/批注

## 4. 输出结构

- 初步结论：只能基于文本判断风险与完整性，不对合同法律效力做最终结论；
- 关键条款摘录与引用；
- 潜在风险/漏洞；
- 缺失或表述不清的条款；
- 签约/投保前建议；
- 需要用户补充的信息。

## 5. 模型与降级

- 配置了 DeepSeek/Qwen 文本模型时，使用 RAG + LLM 生成结构化审查报告；
- `llm.provider=offline` 时使用规则检查：识别关键条款是否存在、提取风险关键词并给出检查清单；
- 扫描版 PDF 如果没有可提取文字，会提示先做 OCR；
- 文件最大 20 MB，可在 `documents.max_file_mb` 调整。
