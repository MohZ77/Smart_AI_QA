# 业务场景与项目范围

## 1. 业务场景

金融产品条款长、更新频繁、合规要求高。基金、保险、债券和银行理财的风险收益特征差异大，普通投资者很难仅凭销售页面理解等待期、免责、费率、回撤、赎回条件和适当性要求。

本项目面向金融机构的智能问答工作台，提供四类能力：

- 产品条款问答：等待期、免责、理赔、退保、续保、费率、风险等级；
- 多资产检索：基金、保险、债券、银行理财、股票和宏观研报；
- 合同与条款审查：上传 PDF/Word/Markdown 后定位风险和待核对项；
- 合规辅助：输入预检、输出审查、适当性过滤、引用溯源和审计回放。

## 2. 核心问题

- 条款和专业术语分散在 PDF、网页、研报和内部 FAQ 中，检索成本高；
- 通用大模型容易把相似产品条款混在一起，必须限制在检索证据内回答；
- 金融建议不能承诺收益、不能推荐超出客户风险承受能力的产品；
- 每条建议需要能追溯到原文，便于业务复核和监管检查。

## 3. 当前实现范围

仓库提供可运行的端到端实现：

- 39 部国家金融监督管理总局官方法规 PDF；
- 示例基金说明书、保险条款和研报；
- FAQ、评测集和自动化测试；
- 本地向量库与 Milvus 双后端；
- 哈希向量与 BGE-M3 双 Embedding；
- 离线抽取式模型与 Qwen/DeepSeek 在线模型双模式。

当前数据用于工程验证，不代表生产数据规模。

## 4. 非目标

- 不替代持牌投资顾问、保险顾问或法律意见；
- 不对保险合同效力、承保结果或理赔结果作最终判断；
- 不在缺少授权数据的情况下生成法规、研报或产品条款；
- 不把本地压测结果当作生产容量承诺。

## 5. 生产接入前提

1. 由业务方提供机构授权的产品说明书、条款、研报和 FAQ；
2. 明确用户、顾问、客户和租户的身份关系，以及客户画像授权；
3. 接入企业统一登录、网关审计和数据权限；
4. 使用真实脱敏评测集验证召回、引用、合规和拒答；
5. 按实际 DAU、峰值并发和 LLM 配额做容量规划与压测。

业务规模、DAU、MAU、并发量和准确率应以接入方的立项材料和实测报告为准，代码仓库不固化这些数字。
